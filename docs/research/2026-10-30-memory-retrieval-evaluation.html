Memory retrieval: small held-out check

Agent Home · 30 October 2026 · Node v22.19.0 · deterministic run, no provider calls

What this run establishes: production FTS returned no results for the 10 paraphrased or unknown questions in this fixture and abstained on all of them. That is a fixture-specific lexical miss, not an estimate of production accuracy. Embedding and typed-choice arms are wired and mocked in tests, but have not been measured against live models. No paid calls were made.

Fixture and observed baseline

Eight current Alpha facts; one Alpha memory made stale by replacing its source at the same revision; one fact only in Beta. Ten questions: four development and six held-out, with six answerable paraphrases and four unknowns. Retrieval calls use the production searchPromptMemories API, which filters stale references before returning prompt candidates.

Candidate model facts

  • BAAI’s model card identifies BGE base v1.5 as MIT-licensed and recommends the query prefix “Represent this sentence for searching relevant passages:”; passage text receives no prefix. English context limit is 512 tokens.
  • The OpenRouter public embeddings catalog currently identifies API ID baai/bge-base-en-v1.5 and canonical slug baai/bge-base-en-v1.5-20251117. The harness checks both before a live embedding request; catalog pricing is an estimate only, never a measured charge.
  • Cloudflare’s Clef announcement describes Clef Flash typed decisions and its open-weight release. The harness uses OpenRouter’s typed decision endpoint with a fixed set of fresh fact IDs plus an abstain option; it does not send gold labels.
  • The OpenRouter embeddings API documents indexed vector responses and usage. The harness validates unique result indexes, dimensions, and finite vector values; it calibrates its abstention cutoff on development queries only. Numeric cost is recorded only when returned; if absent, bounded read-only generation-cost reconciliation runs before any second paid arm.

Safety and next measurement

Provider payloads are assembled only from current Alpha rows returned by the production freshness-gated search API. The fixture asserts that neither stale text nor Beta-only text reaches either provider request. Gold labels are used locally for scoring and never included in provider state. No memories are automatically written. Live execution is opt-in, reads the OpenRouter key only through the home key store, uses no retries, and suppresses raw provider errors. Before a paid call, it creates an exclusive private JSONL receipt in a fresh BENCH_RESULTS_DIR; each intent and response is fsynced before validation continues. Existing receipt files block replay.

Do not add semantic retrieval to normal prompt construction based on this run alone. The next useful measurement is one explicitly approved, low-budget live run of these fixed cases, with dev-only threshold calibration and held-out scoring after the threshold is frozen. Until then, keep the current lexical behavior and treat semantic ranking gains and token savings as unknown.

Reproduce the free baseline: cd runner && node benchmarks/memory-retrieval.mjs. Live mode is --live and requires a pre-created fresh results directory in BENCH_RESULTS_DIR; it is intentionally not run in this evaluation.
